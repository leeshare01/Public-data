# UIL-AQA 模型理解---## Q1: 模型的整体 pipeline 是什么？**问**: 之前跑的模型是视频输入到关键帧采样然后用特征提取，然后才引入训练的对吗？**答**: 是的，整体 pipeline 分两个阶段：### 阶段1：离线特征提取（不参与训练）```原始视频 → 均匀采样768帧 → Video Swin Transformer / I3D 提取特征 → 保存为 .npy 文件```从 `dataloader/dataloader_logo.py:35` 可以看到均匀采样逻辑：```pythonselected_indices = np.linspace(0, len(image_list) - 1, 768, dtype=int)```### 阶段2：训练阶段（TQN + Evaluator）```.npy 特征文件 → 填充/截断到固定长度 → TQN (可学习查询 + Transformer解码器) → Evaluator → 最终分数```默认配置下（`split_feats=True`），训练时**不经过原始视频**，直接加载已提取好的 `.npy` 特征：- `data["video"] = torch.tensor(0)` （哑值占位）- `data["feats"]` = 预提取的特征数组- Backbone（ViViT/I3D）在训练中**完全不参与计算**当 `split_feats=False` 时，才从原始帧经过 backbone 实时提取特征（默认不使用此模式）。---## Q2: Fis-V 和 RG 训练时是否使用预提取特征？**问**: 现在训练 Fis-V 和 RG 的模型都是直接使用特征提取之后的结果对吗，相当于不用数据预处理部分对吗？**答**: 完全正确。三个数据集都使用预提取特征，训练时不涉及任何视频预处理：| 数据集 | 特征来源 | 特征目录 | 配置项 ||--------|---------|---------|--------|| **LOGO** | I3D | `logo_feats/` | `presave` || **RG** | Video Swin Transformer | `swintx_avg_fps25_clip32/` | `presave_feature` || **Fis-V** | Video Swin Transformer | `swintx_avg_fps25_clip32/` | 硬编码 `self.presave = True` |三者配置均为 `split_feats=True`，数据加载时直接 `np.load()` 读取 `.npy` 文件。### 关键代码路径**RG** (`dataloader/dataloader_gymnastic.py:65`):```pythondata["feats"] = np.load(os.path.join(self.args.presave_feature, `q_number`，即可学习查询的数量）：| 数据集 | q_number | 处理方式 ||--------|----------|---------|| LOGO | 48 | 填充/截断至 103（`max_len`） || RG | 68 | 随机截取 68 段或零填充 || Fis-V | 136 | 随机截取 136 段或零填充 |### Backbone 配置的说明三个配置文件都写 `backbone = "vivit"`，但在 `split_feats=True` 模式下 backbone 实际不被调用。配置保留的原因：- 方便切换到 `split_feats=False` 模式进行端到端训练- 模型结构定义需要 backbone 占位---## 模型架构总览```┌─────────────────────────────────────────────────────────┐│                    离线阶段（特征提取）                    ││  原始视频 ──→ 均匀采样768帧 ──→ Swin/I3D ──→ .npy文件    │└─────────────────────────────────────────────────────────┘                           ↓┌─────────────────────────────────────────────────────────┐│                     训练阶段（本工作的核心）               ││                                                         ││  .npy特征 ──→ TQN (Transformer解码器) ──→ Evaluator ──→ 分数 ││                │                        │               ││                ├─ 可学习查询 (q_number)    ├─ 均值分支      ││                ├─ 自注意力               ├─ 权重分支      ││                ├─ 交叉注意力             └─ 加权求和      ││                └─ 位置编码                               ││                                                         ││  损失: MSE(回归) + KL散度(注意力对齐)                     ││  评估: SRCC (Spearman相关系数)                            │└─────────────────────────────────────────────────────────┘```## 核心创新点TQN（Temporal Query Network）的创新在于对**已提取好的特征**做时序建模和可解释性分析：1. **可学习查询**：每个查询对应一个时间片段，自动学习关注视频的不同部分2. **注意力机制**：自注意力（查询之间）+ 交叉注意力（查询到特征），产生可解释的注意力图3. **双分支评估**：均值分支预测每个片段的质量分数，权重分支预测每个片段的重要性，加权求和得到最终分数特征提取本身（Swin Transformer / I3D）用的是现成预训练模型，不是本工作的核心贡献。---## Q3: I3D 是否需要预训练？现行方法一般怎么做？**问**: 如果我想自己做特征提取，I3D 是否需要预训练，现行的方法一般是怎么做的？**答**: I3D **必须要预训练**，否则提取的特征毫无意义。### 为什么必须预训练I3D 有约 12M 参数，而 AQA 数据集通常只有几百个视频样本。从零（随机初始化）训练 I3D 会严重过拟合，学到的特征也无法泛化。I3D 的核心价值在于**将 Kinetics-400（30 万+ 动作识别视频）上学到的时空特征迁移到 AQA 任务**。代码证据：`models/__init__.py:8` 中 `build_backbone` 虽然写了对 I3D 的支持，但返回的是 `I3D().cuda()`——随机初始化，未加载任何预训练权重：```pythonif backbone == "i3d":    from models.backbone.i3d import I3D    return I3D().cuda()  # 无预训练权重加载```三个配置文件虽然都定义了 `I3D_ckpt_path`（指向 `/home/xu/repo/CoRe/MTL-AQA/model_rgb.pth`），但 `build_backbone()` 从未使用该变量。这是因为 `split_feats=True` 模式下 backbone 根本不会被调用，配置项仅作占位。### 本项目的实际做法| 数据集 | 使用的特征提取器 | 目录名 ||--------|-----------------|--------|| LOGO | I3D (Kinetics-400 预训练) | `logo_feats/` || RG | Video Swin Transformer | `swintx_avg_fps25_clip32/` || Fis-V | Video Swin Transformer | `swintx_avg_fps25_clip32/` |从 RG/Fis-V 的特征目录名 `swintx_avg_fps25_clip32` 可以反推提取方式：| 参数 | 含义 ||------|------|| `swintx` | Video Swin Transformer || `avg` | 对 clip 内的时间维度做平均池化 || `fps25` | 25 帧/秒采样 || `clip32` | 每 32 帧为一个 clip |### AQA 领域的通行做法```视频 → 均匀采样N帧 → 切分为固定长度clips → 预训练backbone提取特征 → 时间池化 → .npy保存```常用的预训练 backbone：| Backbone | 预训练数据集 | 输出维度 | 特点 ||----------|------------|---------|------|| I3D | Kinetics-400 | 1024-d | 经典方案，大多数 AQA 论文使用 || Video Swin Transformer | Kinetics-400/600 | 1024-d | 本项目 RG/Fis-V 使用 || CLIP-ViT | WebImageText 400M | 768/1024-d | 近年趋势，图文对齐更强 || VideoMAE | Kinetics-400/700 | 768/1024-d | 自监督预训练 |核心原则：**特征提取使用在大规模数据上预训练的模型并冻结；AQA 的时序建模和评分网络在提取好的特征之上训练**。### 如果自己实现特征提取关键步骤：1. **下载预训练权重**：如 Kinetics-400 预训练的 I3D（PyTorch 版可从 `piergiaj/pytorch-i3d` 获取）或 Video Swin（`mmaction2` / OpenMMLab）2. **帧采样**：对每个视频均匀采样（如 768 帧，或按目标 fps 采样）3. **组织 clips**：将帧组织成固定长度 clips（如 32 帧/clip，stride 可设重叠或不重叠）4. **过 backbone**：每个 clip 通过 backbone 前向传播，取特定层输出（I3D 取 `mixed_5c` 后的 avg_pool → 1024-d；Swin 取最后层输出）5. **时间池化**：对每个 clip 的时间维度做 average pooling，得到 `(1, 1024)` 的 clip 级特征向量6. **汇总保存**：所有 clips 的特征组成 `(num_clips, 1024)` 矩阵，`np.save()` 保存为 `.npy`示例伪代码：```pythonimport torchimport numpy as np# 加载预训练 I3Dmodel = I3D(num_classes=400, modality='rgb')model.load_state_dict(torch.load('model_rgb.pth'))model.eval().cuda()# 均匀采样 768 帧frames = load_video_frames(video_path)indices = np.linspace(0, len(frames)-1, 768, dtype=int)sampled = [frames[i] for i in indices]# 分成 48 个 clip，每个 16 帧 → reshape 为 (48, 3, 16, 224, 224)clips = sampled.reshape(48, 16, 3, 224, 224).permute(0, 2, 1, 3, 4)# 逐 clip 提取特征features = []for clip in clips:    with torch.no_grad():        _, feat = model(clip.unsqueeze(0).cuda())  # feat: (1, 1024)    features.append(feat.squeeze().cpu().numpy())features = np.stack(features)  # (48, 1024)np.save('output.npy', features)```
