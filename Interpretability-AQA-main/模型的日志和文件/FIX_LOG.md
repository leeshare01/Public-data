`seed_worker(args.seed)`**详细描述:**旧 `worker_init_fn` 使用 `np.random.get_state()[1][0]` 作为基础 seed，该值取自主进程调用时的 numpy 运行时状态。在 Windows `spawn` 多进程模式下，子进程的 numpy 为默认状态，不受 `cfg.seed` 控制。导致 seed=999 同样配置多次运行，数据随机裁剪位置不一致，训练结果不可复现（Run1 SRCC=0.679 vs Run2 SRCC=0.412）。**关键代码变更:**- `seed_worker(base_seed)` 直接将 `cfg.seed` 作为基础种子，worker N 获得 `seed + N` 的确定性种子- 4 个 dataloader 统一传入 `args.seed`，跨 run 数据裁剪位置完全确定### [2026-05-20] 修复 seed_worker 闭包不可 pickle 的问题**改动文件:**- `utils/dataloader_utils.py` — `seed_worker` 从闭包改为模块级 `_SeedWorker` 类**详细描述:**Windows 下 PyTorch 使用 `spawn` 启动 DataLoader worker，`worker_init_fn` 需要能 pickle。闭包（嵌套函数 `_worker_init_fn`）不属于模块顶层对象，pickle 失败：`AttributeError: Can't pickle local object 'seed_worker.<locals>._worker_init_fn'`。**关键代码变更:**- 新增模块级 `class _SeedWorker`，用 `__call__` 实现可 pickle 的 worker_init_fn- `seed_worker(base_seed)` 改为返回 `_SeedWorker` 实例---### [2026-05-20] 理解：旧代码为何产生不可复现的结果**验证结果:**修复后 seed=999 同配置连续两跑，SRCC 均为 0.6558495525068597，RL2 均为 2.307189832963358，完全一致。**根因分析:**两个非确定性来源叠加导致旧代码 Run1 (0.679) 和 Run2 (0.412) 的巨大差异：| 来源 | 机制 | 影响 ||------|------|------|| `worker_init_fn` 种子漂移 | `np.random.get_state()[1][0]` 取父进程运行时状态，跨 run 不同 | 视频随机裁剪帧位置不同 → 输入数据不同 || `dino_loss` 噪声 | 训练时 `torch.randn` 加噪，数据顺序差一点 → 噪声序列差一点 → 梯度累积放大 | 优化轨迹分叉 |两个叠加：数据不同 + 噪声不同 → 优化走向不同 → 结果差异可达 0.27 SRCC。**为何 dino_loss=False 时差异小:**Run3 (0.656) vs Run5 (0.656) 差异仅 0.0003。关闭 dino_loss 去掉了训练时噪声，只剩下数据裁剪一个不确定性源，方差大幅缩小。**修复后的确定性链:**`cfg.seed=999` → `_SeedWorker(999)` → worker N seed=999+N → `np.random.randint` 裁剪位置确定 → 输入数据一致 → 结果可复现。---### [2026-05-21] 理解：当前代码版本与论文的架构差异**当前最佳结果 vs 论文:**| 数据集 | 日期 | 模型配置 | 我们的结果 | BMVC 2024 论文 | IJCV 2025 论文 | vs BMVC | vs IJCV
